# DocFind · 大文本检索工具

用来在GB级别的 txt、log、csv、sql，还有MyISAM的MySQL表文件里搜内容，比如找编号 `12345`。
整个工具就两个单文件程序，零额外依赖：

| 文件 | 怎么用 | 运行环境 |
|---|---|---|
| `文档检索.html` | 可视化网页版，双击直接打开，拖文件或者整个文件夹进去搜索 | Chrome / Edge；中文GB18030解码靠浏览器 |
| `文档检索.py` | 命令行版本，适合超大文件、批量目录、写脚本自动跑 | Python3.8及以上，只用Python自带标准库 |

> 所有文件都在你本地电脑读取，**不会上传任何数据到网上**。网页版全程没有网络请求。
> 中文文件名不好敲的话，两个文件随便改名，比如改成 `docfind.py`，命令里同步换成新名字就行。

### 网页版

1. 双击 `文档检索.html`，用Chrome或者Edge打开

## 网页版详细说明

页面左边是设置区，分成4块，右边是搜索结果。

### 1. 数据源

- **拖入文件或者文件夹**：支持多选，文件夹会自动往子文件夹里面找文件
- **扩展名过滤**：默认只读取 `.txt,.log,.csv,.tsv,.md,.json,.jsonl,.ini,.dat,.sql,.frm,.myd,.myi`。留空就是读取所有文件；修改过滤规则后，需要重新选择文件才生效
- **MyISAM三件套提示**：如果你拖进来同名的 `.frm/.MYD/.MYI`，工具会自动识别成一张数据表，告诉你这三类文件有没有齐全；只传 `.MYI` 会提醒你补上 `.MYD`。这里还有一键复制导出命令的按钮，直接生成myisamchk和mysqldump模板
- **示例按钮**：不想找本地文件的时候点它，自动生成带 `12345` 的测试数据，用来试功能

### 2. 检索内容

- 多个关键词用空格或者换行隔开，搭配多关键词逻辑：OR（任意一个匹配就命中）、AND（全部关键词都要匹配）
- 忽略大小写：默认勾选
- 建索引（重复搜索提速）：把读取到的行缓存到浏览器内存，换关键词不用重新读文件。这个只是前端缓存，和MySQL的.MYI索引没有关系。缓存最多存150万行，数据量很大的时候建议关掉
- 操作按钮：开始检索 / 暂停/继续 / 结束。快捷键：`Ctrl+Enter` 开始检索，`Esc` 结束

#### 暂停、查看结果、继续搜索怎么用

1. 扫描中途点暂停，立刻展示已经找到的内容，顶部黄色提示条提醒。可以浏览结果，也可以直接导出
2. 点继续，从刚才读到的位置接着扫描，已经找到的内容不会丢失、不会重复查找
3. 点结束，停止扫描，保留现有结果，按钮复位，开启新一轮搜索

原理：扫描到数据块边界停下，已经读到的字节、行号、没解码完的中文、上下文缓存全部保留，不会乱码。开索引模式暂停，会先用已经缓存好的数据过滤出结果。

> 注意：暂停的时候修改关键词不会生效，匹配规则在点开始的时候就固定好了。想换关键词，先点结束再重新搜索（索引模式除外，索引模式改关键词可以实时过滤）
>
> 网页版的暂停缓存只存在页面内存里，刷新或者关掉页面就清空了。想要关机之后继续搜，用命令行的断点功能
>
> 检索运行的时候，清空、添加文件、载入示例按钮会锁定，防止结果错乱

### 3. 匹配规则

| 匹配方式 | 说明 | 搜12345示例 |
|---|---|---|
| 包含（子串，默认） | 一行里面任意位置出现关键词就算匹配 | `ORD-12345-2026`、`123456` 都命中 |
| 整词 / 完整编号 | 关键词前后不能紧贴字母、数字、下划线；中文挨着数字不算边界 | `123456` 不会命中 |
| 字段相等 | 按分隔符切割成多列，某一列的值和关键词完全一模一样 | 只有 `...,12345,...` 这种完整列才命中 |
| 正则表达式 | JS正则语法 | `1234[5-7]`、`ORD-\d{5}` |

- **字段分隔符**：选「字段相等」才会出现，默认逗号，`\t` 代表制表符
- **编码选项**：自动识别 / UTF-8 / GBK·GB18030 / UTF-16 LE / UTF-16 BE / Big5。中文乱码的时候手动切换，二进制文件里的中文片段也会按这个编码解析
- **上下文行数**：默认2行，范围0–20
- **最多命中条数**：默认2000，范围1–100000
- **MySQL二进制文件选项**：自动识别 / 全部按二进制读取 / 全部当成文本；「同时搜索数字的INT二进制编码」默认开启，误报太多可以关掉

### 4. 合并为单个txt

按照你选中文件的顺序合并，点合并并下载，生成 `merged_时间戳.txt`

- **输出编码**：UTF-8带BOM（Windows记事本打开不乱码，默认）、UTF-8无BOM、原样拼接（速度最快，要求所有文件编码一致）
- **文件之间分隔**：空一行、插入文件名标记、直接拼接
- 可选：合并前按文件名排序，带进度条，可以随时取消

合并不是简单字节拼接：逐个文件识别编码、解码，再统一编码输出。UTF-8、GBK、UTF-16混在一起合并也不会乱码。多余的BOM会删掉，只在最终文件开头保留一个；文件结尾缺换行，会自动补上，避免两行粘在一起。流式分片处理，大文件不会占满内存。

> 网页版导出只能是UTF-8，浏览器限制。想要GBK、UTF-16输出，或者超大文件合并，用命令行 `--merge`
>
> .frm/.MYD/.MYI 是二进制文件，合并的时候会自动跳过，不会混进去变成乱码

### 结果区

顶部统计：命中数量、扫描行数、已读取大小、文件总数、耗时；下面是进度条和结果列表。命中关键词高亮，上下文灰色显示，超长行页面上截断，导出文件里面保留完整原文。

工具栏支持导出CSV/TXT/JSON、清空结果。

## 命令行版详细说明

### 基础格式

```bash
python 文档检索.py <检索词> <文件/目录/通配符> [选项]
```

目录会递归查找子文件，通配符自动展开；`-` 代表从管道读取内容。

检索词可以不传，`--merge` 合并、`--mysql-guide` 查看表信息不需要检索词。

随时输入 `python 文档检索.py -h` 查看全部参数和示例。

### 参数清单

#### 检索条件

| 参数 | 说明 | 默认 |
|---|---|---|
| pattern | 检索关键词 / 正则（位置参数） | — |
| paths | 文件、文件夹、通配符，支持多个；`-` 读取管道 | — |
| `-k, --keyword` | 追加关键词，可重复写多次 | `[]` |
| `--and` | 多关键词全部匹配才命中，默认是任意一个匹配 | 关闭 |
| `-i, --ignore-case` | 忽略大小写 | 关闭 |

#### 匹配规则

| 参数 | 说明 | 默认 |
|---|---|---|
| `-m, --mode` | `contains` 子串 / `word` 整词 / `field` 字段相等 / `regex` 正则 | `contains` |
| `--regex` | 开启正则模式，等价 `--mode regex` | 关闭 |
| `--sep` | field模式的列分隔符，`\t` 代表制表符 | `,` |
| `--col` | field模式只匹配第N列，从1开始 | 所有列 |
| `-C, --context` | 附带输出命中行前后N行 | `0` |
| `-n, --limit` | 最多返回多少命中，0=不限 | `2000` |

#### 输入输出

| 参数 | 说明 | 默认 |
|---|---|---|
| `-e, --export` | 导出文件，后缀支持 .csv / .txt / .json | 不导出 |
| `--format` | `auto` 按后缀识别 / csv / txt / json | `auto` |
| `--max-print` | 终端屏幕最多打印多少行，0=不限 | `500` |
| `--count` | 只统计命中总数，不输出内容 | 关闭 |
| `--no-color` | 关掉终端彩色高亮 | 关闭 |
| `-q, --quiet` | 不打印进度信息 | 关闭 |
| `--progress-every` | 每扫描多少行打印一次进度 | `500000` |

#### 编码与文件筛选

| 参数 | 说明 | 默认 |
|---|---|---|
| `--encoding` | auto / utf-8-sig / gb18030 / utf-16 / gbk / big5 / latin-1；二进制模式下用来解析中文片段 | `auto` |
| `--ext` | 递归目录时的扩展名过滤，逗号分隔；空字符串=全部文件 | 默认后缀同上 |
| `-j, --jobs` | 同时并行扫描的文件数量 | `1` |

> 单独指定某一个文件的时候，不受扩展名过滤限制

#### MySQL二进制文件相关

| 参数 | 说明 | 默认 |
|---|---|---|
| `--binary` | auto 只识别MyISAM三件套 / force 全部按二进制字节流读 / off 全部当成文本 | `auto` |
| `--no-bin-number` | 关闭数字定长编码搜索，减少误报 | 关闭 |
| `--mysql-guide` | 只打印数据表文件关系、导出SQL步骤，不检索，传目录可以列出里面所有表 | 关闭 |

#### 断点续查

| 参数 | 说明 |
|---|---|
| `--checkpoint FILE` | 把进度保存成JSON断点文件；按Ctrl+C会收尾保存进度和结果 |
| `--resume FILE` | 读取断点文件继续搜索，自动恢复关键词、路径、已有结果 |

#### 合并模式

| 参数 | 说明 | 默认 |
|---|---|---|
| `--merge OUTPUT` | 合并模式，把后面的文件按顺序写入OUTPUT，不需要检索词 | — |
| `--merge-sep` | newline 空一行 / name 插入文件名标记 / none 直接拼接 | `newline` |
| `--merge-encoding` | utf-8-sig / utf-8 / gb18030 / utf-16 | `utf-8-sig` |

### 常用命令示例

```bash
# 递归扫描目录，自动识别编码，查找12345
python 文档检索.py 12345 "D:\data\"

# 整词匹配，避免123456误命中，附带前后2行上下文
python 文档检索.py 12345 "D:\data\" --mode word -C 2

# CSV文件，只匹配第一列完全等于12345
python 文档检索.py 12345 "D:\data\*.csv" --mode field --sep , --col 1

# 正则匹配，忽略大小写
python 文档检索.py "ORD-\d{5}" "D:\dump\*.sql" --regex -i

# 一行里面同时包含12345和李四两个关键词
python 文档检索.py -k 12345 -k 李四 --and "订单.txt"

# 只统计数量、并行扫描
python 文档检索.py 12345 "D:\logs\" -j 4 --count

# 搜索+导出结果文件
python 文档检索.py 12345 "D:\logs\" -C 2 --export result.csv

# 读取管道输入
type big.txt | python 文档检索.py 12345 -
```

## 断点续查（命令行版）

按下 `Ctrl+C` 不会直接丢掉已经找到的结果。程序会先标记停止，等当前行/数据块处理完，输出已命中内容、导出文件，同时写入断点JSON。

```bash
# 开始搜索，保存断点，随时Ctrl+C终止
python 文档检索.py 12345 huge.log -C 1 --checkpoint job.json
# 从断点继续搜索
python 文档检索.py --resume job.json
# 续跑的时候还可以改参数，比如取消命中上限
python 文档检索.py --resume job.json --limit 0
```

断点里面记录：原始参数、文件列表、已经扫完的文件、当前文件字节偏移、行号、上下文缓存、二进制扫描临时数据、全部已经找到的结果。续跑不会重复扫描、不会重复命中。全部扫描完成后，断点文件自动删除。

### 断点限制

- 开启断点之后，自动变成单文件顺序扫描，并行参数 `-j` 失效
- 不支持管道输入 `-`，管道没有固定字节位置，没法回退
- UTF-16文件断点降级：中断之后这个文件从头重扫，但不会出现重复结果
- 断点文件自带版本号，版本不匹配直接报错，防止错误解析

> 断点文件里保存了所有命中原文，有敏感数据注意保管

## MySQL .frm / .MYD / .MYI 说明

这三个是MyISAM数据表的二进制文件，它没有"行"这个概念。工具是直接按字节流扫描，不是按文本解析。

- 提取里面可打印的字符串片段：找到MYD里的字段文本、frm里的表名和字段名、MYI里的索引键
- 搜数字的时候，额外匹配2/3/4/8字节小端整数编码，所以INT类型的数字也能搜到；结果会标注十六进制偏移和数值
- 结果里的编号是字节偏移地址，不是行号

```bash
python 文档检索.py 12345 "D:\mysql\data\mydb\"              # 自动识别三件套
python 文档检索.py 12345 orders.MYD                          # 只扫数据文件，推荐，速度最快
python 文档检索.py 12345 orders.MYD --no-bin-number          # 关闭数字编码匹配，减少误报
python 文档检索.py 12345 "D:\mysql\data\" --encoding gb18030 # 数据库是GBK编码
python 文档检索.py --mysql-guide "D:\mysql\data\mydb"        # 查看表文件完整性、导出指引
```

### 三个文件怎么选

| 传入文件 | 能查到内容 | 速度 |
|---|---|---|
| 只传 .MYD（优先推荐） | 记录里的字符串、INT数字 | 最快，噪音最少 |
| 三个一起上传 | 上面全部内容，再加表名、字段名、索引键，干扰内容变多 | 慢，扫描量更大 |
| 只传 .MYI | 只有索引键，索引还可能压缩 | 查不到真实记录内容 |
| 只传 .frm | 只有表名、字段定义 | 查不到业务数据 |

同名三件套只是给你展示文件齐不齐，**工具不会跨文件关联数据，也不会用MYI加速MYD查询**。

> 重要提醒：字节扫描只能粗略定位。日期、浮点数、压缩表、InnoDB的ibd文件，都没法稳定解析。数字编码匹配经常出现误报。想要精准查询，最好把整套文件放到同版本MySQL里，mysqldump导出成sql文本，再用本工具检索。

## 合并模式

```bash
python 文档检索.py --merge all.txt "D:\data\*.txt"
python 文档检索.py --merge all.txt a.txt b.txt c.txt
python 文档检索.py --merge all.sql "D:\dump\*.sql" --merge-sep name --merge-encoding gb18030
```

逐个读取文件，自动识别编码解码，统一按你指定的编码写出。不同编码混在一起合并不乱码。只在最终文件开头保留一个BOM。文件末尾缺换行自动补齐。流式写入，不会占用大量内存。

如果输出文件放在你要合并的文件夹里面，程序会自动跳过它，避免自己合并自己。二进制MyISAM文件会跳过并提示。

## 场景快速对照

| 需求 | 操作方式 |
|---|---|
| 一堆txt里面找订单号12345 | 网页版拖文件夹；命令行 `python 文档检索.py 12345 目录/` |
| 不想匹配123456这类相近编号 | 匹配方式选整词；命令行 `--mode word` |

| 中文全部乱码 | 编码切换GB18030；命令行 `--encoding gb18030` |
| 查找MyISAM表里面的编号 | 优先只传.MYD；加 `--no-bin-number` 减少误报 |
| 很多txt合并成一个文件 | 网页版点合并下载；需要GBK输出、大批量文件用命令行--merge |
| 扫一半想看结果，之后继续搜 | 网页版暂停；命令行Ctrl+C + --resume |
| 同一批文件反复换关键词搜索 | 网页版勾选建索引 |
| 脚本定时跑、只统计数量 | `--count --export result.csv -j 4 --quiet` |

## 限制和排错

### 工具能力边界

- 二进制字节扫描只能粗略定位，不是数据库精确查询。日期、浮点数、压缩表、InnoDB的ibd不支持可靠解析
- 网页版索引缓存上限150万行，大数据量关掉索引
- 网页版暂停缓存只在页面内存，刷新丢失；网页导出只能UTF-8
- 网页版GB18030解码依靠浏览器TextDecoder能力
- 断点模式不支持并行、管道，UTF-16只能文件级断点
- 合并自动跳过二进制表文件；原样拼接模式要求所有文件编码一致

### 常见问题

| 现象 | 处理办法 |
|---|---|
| 中文乱码 | 手动切换编码为GB18030，命令行加 `--encoding gb18030` |
| 一个文件都扫描不到 | 检查扩展名过滤框；单独指定文件不受过滤限制 |
| 大量无关内容命中 | 换成整词/字段相等模式；二进制文件关闭数字编码匹配 |
| 只传.MYI搜不到内容 | MYI是索引文件，没有记录正文，补上.MYD |
| 暂停之后改关键词不生效 | 先结束本次检索，重新开始；索引模式可以直接改关键词 |
| 命令行输出中文报错 | 程序自动设置stdout为UTF-8；重定向保存文件用UTF-8编辑器打开 |
| --help里的示例命令跑不通 | 示例里的路径和文件名换成你本地真实文件 |

## 性能参考

测试环境：Python3.11.9，14MB、20万行单文件，只统计命中数量，耗时约0.17秒。固态、机械硬盘速度差距很大，只用来参考量级。

扫描耗时主要看总字节大小，少传无关文件就能提速。二进制文件按1MB分块读取。

内存占用和文件大小无关，只和上下文行数、命中条数挂钩，流式读取，只保留命中内容和上下文。

索引模式用内存换速度，适合中小数据集反复检索。
